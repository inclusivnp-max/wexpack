# WexPack: ускорение без изменения архивов

14 ноября 2026. Базовая версия — solid из коммита `2549ebb`.
Это сравнение двух версий одного движка, а не новое соревнование уровней разных архиваторов.

Все 84 созданных архива распакованы и проверены по пути, размеру и SHA256 каждого
файла. На всех 14 сочетаниях «набор × solid/обычный» архивы старой и новой версии
побайтно совпали, включая все три повтора. Ускорение не получено уменьшением окна,
числа проверяемых совпадений, отключением fsync, шифрования или проверки хешей.
Исходники почти не ускорились: для текста остаются дорогими подготовка словаря
и два перспективных кандидата. Эффект зависит от набора, единого множителя нет.

## Что ускорено

1. Для крупных групп четырёхбайтовые ключи отмечаются в однонаправленном битовом
   фильтре. Если бит отсутствует, совпадение отсутствует наверняка. Коллизия
   выполняет прежний точный поиск; положительный ответ не считается совпадением.
   Эвристика разнообразия только включает этот ускоритель, а не меняет поиск.
2. Верхний байт позиции содержит кэш первого байта. Предыдущие позиции
   извлекаются из младших 24 бит; последние три позиции не записываются в цепь,
   поэтому sentinel не пересекается с допустимой записью.
3. Бюджет второго кандидата проверяется по уже записанному префиксу кадра.
   Префикс только растёт. Остановка происходит лишь когда и этот префикс, и STORE
   превышают бюджет. Прежний победитель сохраняется, включая identity при ничьей.
4. Кадр сразу переходит в STORE, когда его префикс уже не меньше полного входа.
   Последующие блоки такой кадр уменьшить не способны.

Формат WXP/WXE не меняется, выбор преобразования и параметры поиска сохранены.
Битовый фильтр требует до 16 МиБ на worker; планировщик учитывает их и при
необходимости уменьшает очередь. Пропуск поиска по отрицательному биту
проверен против того же finder без ускорителя, включая истечение окна.

## Методика и проверки

Те же замороженные семь корпусов предыдущего сравнения, четыре физических ядра
[0,2,4,6], nice=5, до четырёх worker, 512 МиБ, последовательный перемешанный
порядок seed=20261114, прогрев каждой конфигурации, три повтора. Кэш ОС не очищался.
Измеритель C/wait4 не наследует RSS Python; проверка SHA256 выполнена вне таймера.
Шифрование/recovery в сравнении скорости отключены у обеих версий, их алгоритмы
не менялись. Полный тестовый набор отдельно проверяет шифрование и восстановление.
Все обычные и solid-профили используют `--dedup -l 5 --threads 4 --memory-mib 512`.

Базовый набор: 138 тестов. Новый: 143 теста, включая границы бюджета, коллизии,
полное 16-МиБ окно и отсутствие ложных отрицательных ответов битового фильтра.
Clippy с `-D warnings` пройден. Откат исходников проверяется на отдельной копии;
рабочий проект и новая установка остаются изменёнными.

| Свидетельство | Результат | Реализация |
|---|---|---|
| MODIFIED-tests.log | 143 теста прошли | tests/speed.rs; codec/lz.rs |
| BYTE-IDENTICAL.json | 14/14 профилей, 84/84 архива совпали | codec/mod.rs; pipeline.rs |
| results.jsonl | 84/84 извлечения совпали со входом | benchmark.py |
| ROOT/VENDOR-tests.log | Перенесённый код проверен | src; third_party/wexpack |
| ROLLBACK-verification.json | Старый исходный код и поведение восстановлены в копии | ROLLBACK.sh |

Raw-файлы, скрипты стенда, корпус и локальная установка остаются на машине автора;
в Git публикуются этот отчёт и агрегированные `summary.csv`/`summary.json`.
В WEXdesktop заменяется встроенный движок. Открытое окно не закрывается;
новая неизменяемая установка используется после полного выхода и нового запуска.
Обычный профиль создания архивов в GUI остаётся прежним.

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked --release
```
