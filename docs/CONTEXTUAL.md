# Контекстные литералы и четыре расстояния

Архивы с новым кодеком требуют обновлённого движка. Новый движок читает прежние
WXE1/2/3. Контейнер остаётся версии 2: кодек 5 требует обоих обязательных флагов
`STRUCTURED=0x80` и `LITERAL_CONTEXT=0x100`; старый читатель отвергает новый флаг.
Уровни 1–3 и сжатие оглавления сохраняют прежний формат.

## Использование

```sh
cargo build --locked --release
./target/release/wxp pack project.wxp ./src --solid --dedup -l 5 --threads 1 --memory-mib 256
./target/release/wxp verify project.wxp
./target/release/wxp unpack project.wxp -o ./restored
```

Уровни 4–9 автоматически сравнивают старые кандидаты и новый. Без `--solid`
история ограничивается блоком; с ним — независимо декодируемой группой до 16 МиБ.
Контекстные модели оплачивают собственные заголовки и частотные таблицы. Кодер
выбирает только фактически меньший payload; улучшение целого контейнера на любом
входе не гарантировано из-за изменений сжатого оглавления. Дополнительные пробы
увеличивают время упаковки; результаты находятся в отчёте за 15 ноября 2026.

## Кадр и блок

| Поле | Значение |
|---|---|
| CodecType | WexContextual=5 |
| Кадр | W,X,E,0x04; прежний заголовок 24 байта |
| byte 4 / byte 5 | codec=5 / level=4..9 |
| u16 LE offset 6 | bit 0=solid; остальные нулевые |
| Методы блоков | 0..6 прежние; 7=контекстный WXS2 |
| intermediate_size метода 7 | число токенов |

Метод 6 читает только WXS1, метод 7 — только WXS2; перепутанная версия отвергается.
Прежние методы допустимы в кадре 4. Кодек 5/кадр 4 выбираются лишь при фактическом
выборе метода 7 хотя бы одним блоком. Иначе сохраняется кадр 3 или старый кадр.

WXS2 использует заголовок 44 байта: magic W,X,S,0x02; mode-байт с битами 0/2/3
для rANS потока типов/длин/расстояний, бит 1 обязательно нулевой; byte 5 — контекст;
bytes 6..7 — нули. Далее девять u32 LE: token_count, literal_count, match_count,
extra_bit_count, размеры пяти потоков kind/literal/length/distance/extra.
Потоки следуют в этом порядке. Типы raw упакованы LSB-first; 0=литерал, 1=совпадение.
Длины и дополнительные биты сохраняют WXS1: length-3=2^s+extra, s=0..17.

## Банки литералов

Поток литералов начинается с bank_count:u8 и трёх нулей. Каждый банк имеет
12-байтовый дескриптор: decoded_count:u32, payload_size:u32, codec:u8 (0=raw,
1=WAN1 rANS), три нуля. После всех дескрипторов идут payload банков по порядку.
Пустой банк обязательно raw. Сумма decoded_count равна literal_count.

| Контекст | Банки | Правило |
|---|---:|---|
| 0 | 1 | Общая модель, но четыре recent-distance слота |
| 1 | 4 | position modulo 4 |
| 2 | 4 | previous_byte >> 6 |
| 3 | 4 | Предыдущий байт: ASCII whitespace / letter / digit / other |
| 4 | 16 | previous_byte >> 4 |

Начальный предыдущий байт равен нулю. В solid-группе последующие блоки используют
предыдущий байт группы; в обычном кадре каждый блок начинает заново. Позиция —
внутри группы либо блока соответственно. Контексты определяются только уже
восстановленными байтами и не требуют знания будущих токенов.

## Повторы и выбор совпадений

Distance symbols 0..3 выбирают четыре последних различных расстояния по индексу
в move-to-front кэше. Изначально слоты пустые; обращение к пустому слоту ошибочно.
Новый символ 4+s задаёт distance=2^s+extra, s=0..24. После любого совпадения
расстояние переносится в начало без дубликатов; литералы кэш не меняют. Кэш
обнуляется на каждом блоке, даже в solid-кадре. Предел расстояния — 16 МиБ.

Ценовой поиск сохраняет максимальную длину отдельно для каждого из 25 логарифмических
слотов, дополнительно проверяет четыре recent-distance кандидата. Глубина цепочки,
окно истории и горизонт DP ограничены. Разбор 4–7 lazy, 8–9 DP-окно 1024; на позицию
хранится один лучший recent-state, а не все возможные. Цены используют частоты
seed-потоков, не будущего результата; окончательно сравниваются реальные байты.
Старый разбор и WXS1 остаются отдельными кандидатами, поэтому их выбор не зависит
от нового поиска. Рабочая память DP имеет явный предел 29*1024*11 рёбер.

## Проверка

Проверяются размер и число банков, reserved bits, режимы, суммы и точные границы
потоков, частоты и состояния rANS, расход литералов каждого банка, пустые повторы,
слоты, расстояния, padding и обе CRC. Тесты включают явный wire golden, все режимы,
начало нового блока, историю solid, неполные пакеты, malformed-входы, реальные
pack/verify/unpack и шифрование. Таблицы Evidence → Finding → Path с результатами
замеров приведены в отчёте.


## Ускорение без изменения формата

Оптимизированный кодер сохраняет те же модели, порядок выбора и побайтный результат:

- Пять контекстных моделей используют одно кодирование потоков типов, длин,
  расстояний и дополнительных битов. Меняется только пакет литералов; при равенстве
  сохраняется первый режим. Меньший пакет заменяется внутри уже выделенного буфера.
- Модель частот возвращается вместе с rANS-потоком и повторно используется для цен;
  второй проход нормировки исключён. Raw-буфер создаётся лишь при выборе raw.
- Lazy-разбор перебирает только реально существующие слоты длин, один раз считает
  цену расстояния и сохраняет уже рассчитанное lookahead-решение после литерала.
  Кэш действует ровно при неизменных словаре, позиции и recent-state.

Полные старые функции кодирования и lazy-разбора сохранены только в тестах как
исполняемые эталоны. Сравниваются байты, модели цен, выбор контекста и все токены,
включая solid-историю и уровни 4/5/7. Дополнительная запись литерала занимает три
байта; максимум 262144 записи занимает 768 КиБ на блок. Кодеки, флаги,
глубина поиска, границы DP и сжатие не урезаются ради скорости.


## Повторное использование индекса совпадений

Профилирование ELF выявило основную работу в LZ-разборе и двух проходах ценового
парсера. Индекс теперь строится один раз: previous[pos] хранит именно ту голову
хеш-цепочки, которая существовала до вставки pos. При неизменном входе это точный
снимок словаря для данной позиции, а не приближение.

- rewind_to сохраняет границу уже построенной истории в replay_end и меняет
  курсор без обратной записи голов. Во время повтора поиск начинает с
  previous[pos], а не с головы, содержащей более поздние позиции.
- insert в пределах готовой истории только двигает курсор; advance_to пропускает
  готовый диапазон сразу. После этой границы обычная последовательная вставка
  продолжается с актуальными головами, без перезаписи исторических ссылок.
- Граница растёт только при перемотке, не на каждом байте. Дополнительная память
  — одно поле usize в finder; повторно используется уже существующая таблица.

Все цепочки, глубина, окно, кандидаты, порядок равных совпадений и битовый
результат прежние. Первый проход и режим без таблицы предыдущих позиций сохраняют
обычный поиск; перемотка такого режима по-прежнему отвергается.

Тесты сравнивают все матрицы совпадений и repeat-lookup до/после повторов, проверяют
неизменность таблиц, частичный повтор с последующим расширением, 25 слотов
со скалярным независимым эталоном, membership-filter и край 16 МиБ с тегом 0xFF.
Профилировочная копия с таймерами не входит в продукт и не участвует в замерах
ускорения: её включающие интервалы потоков и выборочные оценки — не CPU-time.
